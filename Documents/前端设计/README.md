# Gallery 前端设计材料

本分区用于接收和整理 Gallery 后续前端改版的候选设计材料，包括视觉方向、信息架构、交互流程、响应式布局、可访问性要求和设计系统提案。

放入本分区的文档默认处于**待评审**状态，不会自动覆盖当前规范、ADR、OpenAPI 契约或已经实现的前端行为。设计方案被接受后，应把产品语义写入对应的唯一权威规范；涉及技术方向或已接受决策的变化时，还需同步新增或修订 ADR，再据此安排实现和验证。

## 材料范围

- 用户侧 Gallery 与管理侧 Manage 的信息架构、页面流程和导航设计。
- 视觉语言、设计 token、组件、排版、色彩、图标、动效和密度方案。
- 桌面、窄屏、移动端、触控和 PWA 的响应式设计。
- 键盘、焦点、屏幕阅读器、对比度和减弱动画等可访问性要求。
- 现有页面到候选设计的差异、迁移范围和验收建议。
- 外部图片、字体、图标或其他第三方材料的来源与许可证说明。

本分区不存放 secret、Cookie、真实媒体、私密 metadata，也不把外部产品的数据库、API 或行为作为 Gallery 的兼容目标。

状态使用以下词汇：

- **待评审**：刚加入的候选材料，尚未形成项目决定。
- **评审中**：正在与当前规范、实现和门禁逐项比较。
- **部分采纳**：仅接受其中明确列出的部分，其余内容仍非权威。
- **已采纳**：已同步到对应规范或 ADR；本文件只保留设计来源和追溯关系。
- **已否决**：当前不采用，并记录简要理由或重新审议条件。
- **已替代**：由更新的设计材料取代。

## 评审与落地顺序

1. 先确认材料的目标页面、用户任务、设备范围和可访问性要求。
2. 对照当前 `web/src/gallery`、`web/src/manage`、共享设计系统及真实浏览器门禁，列出保留、修改和删除项。
3. 检查是否改变产品语义、API、Capability、快照、只读 Source 或安全边界。
4. 需要改变权威语义时，先修改对应规范；改变已接受决策时同步 ADR。
5. 再拆分实现任务，并为桌面、窄屏、移动、键盘和屏幕阅读器建立验收证据。
