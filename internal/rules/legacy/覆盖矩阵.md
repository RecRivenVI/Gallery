# 旧配置字段级覆盖矩阵

本文件逐个 JSON Pointer 记录 `gallery-rules.json`（`schema_version: 3`）的每个字段在
`internal/rules/legacy` 转换器中的承接结论。

它存在的理由：**「10 个规则包都能被 `rules.CompilePackage` 接受」只是必要条件，不是转换完整的证据。**
编译成功只说明产出的规则包合法，不说明旧配置的每个字段都被看见过。本矩阵与
`unknown.go` 的未识别字段差集机制互为里外两层——前者给出逐字段的判定，后者保证判定表本身不会
因为漏看一个字段而失效。

## 判定含义

| 判定 | 含义 |
| --- | --- |
| `converted` | 直接转换为某个规则原语或结果字段 |
| `equivalent` | 语义由 Gallery 的另一种机制等价承担，且当前取值确实落在等价范围内 |
| `rejected` | 明确拒绝并登记为未转换 |
| `deferred` | 正式延期到 v1 之后，附重新评审条件 |
| `blocking-unsupported` | **会导致真实行为不正确，必须在 v1 修复** |

`equivalent` 只在**当前取值**落在等价范围内时成立。转换器对这些字段逐项设有取值守卫，取值超出等价
范围时会自动降级为登记，不会因为矩阵写了 `equivalent` 就永远沉默。

## 字段集合的来源与复核方式

字段集合取自真实配置的完整 JSON Pointer 遍历（数组元素归一为 `*`）。本文件**只记录路径与判定，
不记录任何取值**：判定所依据的取值形态在正文中以「当前取值落在等价范围内」这类描述出现，不出现
作者名、作品目录名、metadata 原文、完整 URL 或绝对路径。

复核方式：在本机运行

```powershell
$env:GALLERY_GO = "C:\Users\RavenYin\AppData\Local\CodexToolchains\go1.26.5\go\bin\go.exe"
$env:GOTOOLCHAIN = "local"; $env:CGO_ENABLED = "0"
& $env:GALLERY_GO test ./internal/rules/legacy/ -run TestConvertRealConfigurationWhenAvailable -v
```

该用例只输出计数与字段名，不输出取值；真实配置不可读时跳过。

## 一、必须在 v1 修复（`blocking-unsupported`）

| JSON Pointer | 判定 | 说明 |
| --- | --- | --- |
| `/platforms/*/metadata/author/*`（`$path.author` 项） | `blocking-unsupported` | 作者名的路径回退没有任何原语能承接。`path_match` 的配置是封闭集合（`scope`/`glob`/`title`/`stable_key`/`metadata_file`），既没有 `author_pattern`/`work_pattern`，也没有命名捕获；`fallback`/`stable_key` 只接受 metadata JSON Pointer；CEL 拿得到 `path` 但只能作布尔谓词、不能赋值。后果：metadata 缺作者的作品没有创作者；把作者声明为**只能**从路径取的平台，整个平台都没有创作者 |
| `/platforms/*/metadata/author_id/*`（`$path.author` 项） | `blocking-unsupported` | 同上，作者稳定标识的路径回退无法表达。后果：这些作品的作者退化为逐作品 occurrence，同一作者不再复用同一个 CanonicalCreator |
| `/platforms/*/metadata/title/*`（`$path.author` 项） | `blocking-unsupported` | 「用作品目录的**父目录**（作者段）作标题」无法表达。`path_match` 的 `title` 只支持 `directory_name`，即作品目录名本身。后果：声明该形态的平台，全部作品的标题变成作品目录名而不是作者段 |
| `/platforms/*/structure/author/key_source`（`path_only` 取值） | `blocking-unsupported` | 与上面三行同源：声明作者身份只能从路径取的平台，当前没有任何取值路径 |
| `/platforms/*/metadata/transforms/tags`（`array_or_brace_list` 取值） | `blocking-unsupported`（条件性） | 旧工具把标签的**花括号列表字符串**与 JSON 数组一视同仁地解析为多个标签；Gallery 的取值层只把 JSON 数组识别为多个标签，字符串会成为**一个**标签。后果是标签数量、按标签的搜索与按标签命中的角标全部不同。**触发条件未在本轮核实**：是否真有来源以花括号形态写入标签，需要读取只读媒体根下的真实 metadata，本轮不在允许触碰的范围内。但旧工具不会为一种从不出现的形态声明解析器，因此按会触发处理 |

以上五项的共同修复方向是**给规则原语增加路径段取值能力**（例如让 `path_match` 支持受限的命名捕获，
并允许 `fallback`/`stable_key` 引用捕获名），以及**在取值层支持声明式的多值解析**。两者都在
`internal/rules`，不在本转换器可修改的范围内。

### 本轮已修复、此前属于 `blocking-unsupported` 的项

这些不再是待修项，登记在此以便核对修复是否真的落地。

| JSON Pointer | 此前的错误行为 | 现在 |
| --- | --- | --- |
| `/platforms/*/metadata/author_id/*` | 映射到**作品**的 `external_id`。同一作者的多个作品共享同一个取值，扫描解析阶段命中 `duplicate_external_id` 并返回 `BINDING_REVIEW_REQUIRED`，该 Source 的扫描整体失败 | 落到 `stable_key{target: "creator"}`，即 Creator 的稳定键；回退链长度大于一时不猜测，登记为未转换 |
| 全部 metadata 取值链 | 每条链带 `"default": ""`。求值端只在候选为 nil 时跳过赋值，拿到空串照样赋值：标题被空串覆盖（作品目录名默认值失效，`EnsureCanonical` 对空标题返回校验错误、整次扫描失败）、标签被写成一个空标签 | 不发出 `default`。取不到值留下非必需的 `RULE_SELECTOR_MISSING`，默认值与缺失事实都保留 |
| `/platforms/*/metadata/time/directory_timestamp_timezone` | **未在 `Config` 中声明**，被 `encoding/json` 静默丢弃；转换器只读库级取值。两者不同时产出偏移若干小时却完全合法的发布时间 | 声明并按「平台级 → 库级 → UTC」三级回退取值 |
| `/platforms/*/structure/work/metadata_required`（`false` 取值） | 未声明；转换器无条件下发 `path_match.metadata_file`。扫描器对该字段是**强制**语义——作品目录里缺少该文件即整次扫描失败 | 显式声明为可选时不下发文件名，并登记该平台的 metadata 取值链（如有）随之失效 |
| `/platforms/*/cover/candidates/*/when/rule` | 省略条件、保留候选。该候选的 priority 高于库级显式封面 glob，于是任何存在匹配文件的作品都被它压过显式封面声明 | 条件无法表达时**整条候选不发出**，封面回落到显式 glob 或第一张可见媒体 |

## 三、四个薄弱点的结论

### 1. 路径回退（`$path.author` / `$path.work`）

`path_match` 的命名捕获**不存在**——`pathMatchConfig` 只有 `scope`/`glob`/`title`/`stable_key`/
`metadata_file` 五个字段，`title` 与 `stable_key` 还必须分别恰好是 `directory_name` 与
`relative_path`。此前注释声称「路径回退由 `path_match` 的命名捕获承担」，与代码不符，已改正。

逐项结论：

- `$path.work` 作**标题**：`equivalent`。求值把标题初始化为作品目录名，metadata 链取不到时该值
  保留下来，正好就是 `$path.work` 的语义。此前它被登记为未转换，同时又被 `"default": ""` 覆盖成
  空串——登记说「没承接」，代码却主动破坏了本来成立的承接。去掉 `default` 后等价成立，登记已撤销。
- `$path.author` 作**作者名**、作**作者标识**，以及 `$path.author` 作**标题**：无法承接。缺的是
  「按路径段取值」这一能力本身，而不是某个字段的接法：作品段与作者段的区分在 `PathDatetimePattern`
  里靠前导分隔符解决（相对路径是 `{作者}/{作品}`，作者段在首段、其前没有分隔符），那套做法对
  `work_date` 有效是因为 `work_date` 本身接受一个作用于相对路径的受限正则；`fallback`/`stable_key`
  没有对应入口，CEL 虽然拿得到 `path` 却只能返回 bool。

因此修复必须落在 `internal/rules`，不在本转换器内。

### 2. `metadata.date_title`

结论：**它不改变服务端产出的标题**，但此前的登记理由仍然是错的，已改写。

依据：声明该标志的平台，其标题取值链的第一项就是 metadata 的日期字段——标题本来就是日期原值，
`date_title` 没有再改变服务端产出的任何值。它改变的是**渲染**：旧工具据此把标题按显示时区与
显示格式呈现，而不是显示原始时间戳。Gallery 的 `presentation` 没有对应标志位，因此标题按原值展示。

此前的理由写作「由客户端按 `publishedAt` 呈现」，这条描述会诱导出一个**错误**的客户端实现：标题链
与日期链是两条互相独立的链（标题链在 metadata 缺日期时回退到作品目录名，日期链回退到目录名日期），
metadata 缺日期时二者会分叉，此时用 `publishedAt` 顶替标题会把一个真实的目录名标题替换成日期。
新的登记明确写出「不得用 `publishedAt` 顶替标题」。

### 3. 条件隐藏的 CEL 输入

核实结论：**理由部分属实，此前把两条规则合并成一条登记掩盖了差别，已拆开。**

CEL 环境实际提供的变量是 `source`、`path`、`file`、`metadata`、`candidate`、`params`
（`internal/rules/cel.go` 的 `newCELRuntime`），求值时 `file` 被填为当前文件的
`{path, size, metadata}`（`internal/rules/lifecycle.go` 的 `evalPredicate`）。因此：

- 依赖**同目录兄弟文件扩展名**的那条：理由属实。作品的文件清单存在于求值输入 `DryRunInput.Files`
  中，但没有被放进 CEL 激活记录，所以规则无法看到它。修这一条要么扩展求值上下文，要么新增原语。
- 依赖 **metadata 文本匹配**的那条：理由**不属实**。`metadata` 就在 CEL 上下文里，文件名可由
  `file.path` 取到，`condition{scope: "media", effect: "hide"}` 的求值路径也已实现（`classifyFile`
  对 `effect == "hide"` 会置 `media.Hidden`）。它是可实现的，本轮不实现的理由见矩阵中该行。

### 4. 两个带条件的封面候选

实际后果已核实，且比「范围变宽」更具体：这两个候选的 priority 显著高于库级显式封面 glob 的
priority。省略条件后它们**无条件生效**，于是任何存在匹配文件的作品都会用该文件作封面，压过
`cover.*` 这类明确的封面声明——旧行为里本不该被选中的文件成了封面。

方案与依据：**条件无法表达时整条候选不发出。** 依据是「封面选错」与「封面没选中」的代价不对称：
封面没有显式候选时仍有确定性的回退链（显式 glob → 第一张可见媒体），结果稳定且可解释；封面选错
则是一个看起来完全正常、没有任何 issue 的错误结果。因此宁可不选中。

残余差异：对确实满足旧条件的那部分作品，Gallery 现在会用显式 glob 或第一张可见媒体作封面，
而不是旧工具指定的那一张。该差异已在登记里写明。

## 四、机制说明：未识别字段如何被登记

`Config` 是手写的部分映射，`encoding/json` 对未声明字段一律静默丢弃，没有返回值、错误或日志能
暴露它。`unknown.go` 的 `collectUnknownFields` 用原始 JSON 树与 `Config` 的反射类型逐层比对，把
只出现在原文一侧的键登记为未转换，`Note.Field` 是该字段的 JSON Pointer。

两处刻意的边界：

- 声明为 `json.RawMessage` 的字段（封面候选条件、角标 metadata 取值）是有意保留的原文，其内部
  结构由手写逻辑解释，因此不展开；这些位置在本矩阵中另行逐项判定。
- 未声明的**对象**只登记它自己这一条，不再逐个叶子展开——「整棵子树未被识别」是一条事实，拆成
  十条不会增加信息。

登记出现在结果里**不等于有语义损失**：判定以本矩阵为准，其中若干项的判定是 `equivalent` 或
`rejected`。这个方向的冗余是有意的——把「已经看过并判定为等价」误报成「未识别」只是噪声，反过来
则是本轮要消除的那一类静默丢弃。
