# Gallery 前端设计材料

本分区用于接收和整理 Gallery 后续前端改版的候选设计材料，包括视觉方向、信息架构、交互流程、响应式布局、可访问性要求和设计系统提案。

放入本分区的文档默认处于**待评审**状态，不会自动覆盖当前规范、ADR、OpenAPI 契约或已经实现的前端行为。设计方案被接受后，应把产品语义写入对应的唯一权威规范；涉及技术方向或已接受决策的变化时，还需同步新增或修订 ADR，再据此安排实现和验证。

## 材料范围

- 用户侧 Gallery 与管理侧 Manage 的信息架构、页面流程和导航设计。
- 视觉语言、设计 token、组件、排版、色彩、图标、动效和密度方案。
- 桌面、窄屏、移动端、触控和 PWA 的响应式设计。
- 键盘、焦点、屏幕阅读器、对比度和减弱动画等可访问性要求。
- 现有页面到候选设计的差异、迁移范围和验收建议。
- 外部图片、字体、图标或其他第三方材料的来源与许可证说明。

本分区不存放 secret、Cookie、真实媒体、私密 metadata，也不把外部产品的数据库、API 或行为作为 Gallery 的兼容目标。

- **已替代**：由更新的设计材料取代。

## 评审与落地顺序

1. 先确认材料的目标页面、用户任务、设备范围和可访问性要求。
2. 对照当前 `web/src/gallery`、`web/src/manage`、共享设计系统及真实浏览器门禁，列出保留、修改和删除项。
3. 检查是否改变产品语义、API、Capability、快照、只读 Source 或安全边界。
4. 需要改变权威语义时，先修改对应规范；改变已接受决策时同步 ADR。
5. 再拆分实现任务，并为桌面、窄屏、移动、键盘和屏幕阅读器建立验收证据。

## 2026-07-29 评审与落地结果

本轮只采纳四份材料中能与当前规范、OpenAPI、Capability、快照和安全边界一致的设计意图，具体视觉数值与组件结构均按当前 React 双入口重新实现，没有移植 Legacy 代码。

- 共享基座采用低饱和中性色、四级表面、石墨色主操作、暖金色提醒/修改语义、独立蓝色焦点环、近方形控件、有限浮层阴影和同一套单线 SVG 图标；继续保留浅色、深色、高对比、密度与 reduced-motion 契约。
- 用户端采用桌面常驻侧栏与窄屏抽屉，侧栏组合全局作品搜索、现有页面、规则驱动的平台/来源以及授权后的文件根；作品网格在窄屏保持两列，现有认证、publication 传播、Overlay、路由式 Viewer、离线与错误恢复语义不变。
- 管理端采用常驻控制台侧栏、顶部上下文/快照工具区和窄屏抽屉；语义表格在窄屏按列标签堆叠，已有数据后台刷新时显示非阻塞状态。现有扫描、维护、安全、规则和治理页面及其确认/CAS/无损编辑流程不变。
- 共享动效基座采用直接操纵、即时反馈、普通状态与结构变化四档语义，并重新选择 0/110/180/280ms 与统一曲线；旧时长 token 只保留为别名。浮层、菜单、用户/管理导航和状态反馈共享节奏，reduced-motion 同时由 CSS 归零和逻辑执行层收口。
- 用户端作品网格以稳定 `work.id` 承接同范围搜索、筛选、排序与续页变化：新快照到达前保留旧视觉，但旧网格为 `inert`、`aria-hidden`，不能接收点击或焦点；跨 Source、Library、Creator 不复用旧视觉。可见区附近最多保留有限几何，同键位移、新项显现和不可交互离场副本均可中断并彻底清理；媒体只在实际解码完成后于固定槽位内交叉显现，灯箱拖动/捏合期间不加缓动。
- 管理端没有复制作品卡片的大幅空间动画；只统一导航、按钮、表格悬停、开关、菜单和浮层的局部反馈，轮询数据仍原位更新，不让状态行反复入场。
- 未采纳 Legacy 的无认证、桌面 bridge、服务启停/托盘、直接日志与配置文件访问、绝对路径暴露、空白自动封禁页及任何当前服务端未提供的批量动作。它们不是当前产品能力，也没有被本轮设计推测成新需求。
- 未采纳页码滑轨：当前作品查询是 publication-bound keyset cursor，`total` 还可能只是下限，前端没有可验证的精确页数或任意跳页契约；继续使用连续加载才符合当前规范。标准/紧凑/列表三视图及跨布局封面形变也未在本轮新增，因为当前产品尚未接受对应本地偏好与页面状态模型，不能只为展示动效发明功能。

追加动效切片已通过根级检查（含 TypeScript、ESLint、Prettier、15 个文件 211 项 Vitest、生产 PWA 与 Go 全仓），Chromium/Firefox 各 10 项 mock smoke，以及两浏览器各 21 项隔离真实 `galleryd` 完整链；浏览器证据覆盖同范围旧快照保护、稳定键重排、新旧对象交接、离场副本语义/清理、减弱动画、管理端局部反馈、axe、窄屏焦点及既有全部真实业务/恢复路径。本结果仍不是物理移动设备、人工屏幕阅读器或正式 Web Gate。

EV-113 继续把四份材料要求的可访问降级转成路由级持续门禁：当前用户端 10 条、管理端 9 条路由在桌面与 390×844 窄屏分别进入稳定成功/空/错误状态，Chromium/Firefox 各对 38 个最终 DOM 执行 WCAG 2 A/AA axe；完整 mock smoke 22/22。该自动检查仍不替代真实触控、缩放/高对比、交互状态组合与人工屏幕阅读器。

EV-116 继续把共享视觉/动效基座的降级原则落到 320×800、应用高对比、模拟系统 forced-colors/prefers-contrast 和 WCAG 文本间距的全路由门禁；系统色映射明确区分按钮面与链接前景，管理概览 Grid 也能在 20rem 以下收缩。Chromium/Firefox 完整 mock smoke 24/24。该结果只证明桌面浏览器模拟和 400% 等效重排，不替代实际缩放、物理 Windows High Contrast、真实触控或人工屏幕阅读器。

本轮没有改变产品语义或 ADR-009 接受的 Web 技术栈，因此无需新增 ADR；权威行为仍以 `Documents/规范/`、OpenAPI 与现行 ADR 为准。
