# 文档维护指南

## 职责

- 根 `README.md`：项目介绍、当前能力边界、最小使用入口和导航。
- 根 `AGENTS.md`：长期有效的 Agent 规则、边界和验证要求。
- `reference/`：稳定定义和查表信息。
- `architecture/`：当前实现的关系、数据流和取舍。
- `decisions/`：决策上下文、结论、理由、影响和重新审议条件。
- `development/`：未来计划、开发方式、生成物与门禁。
- `design/`：当前客户端信息架构与交互约束。
- `operations/`：操作者可执行的运行、升级和恢复步骤。
- `validation/`：带日期、输入、环境和局限的证据或历史记录。

## 写作规则

1. 先判断内容是当前事实、决策、计划、历史、推测还是建议。
2. 当前行为必须能定位到源码、配置、契约或当轮执行记录。
3. 无法确认的内容删除或明确列入待确认，不补写“合理猜测”。
4. 同一事实只指定一个主要文档；其它文件写短摘要和相对链接。
5. 使用 Gallery、画廊、`gallery`、`galleryd`、`galleryctl` 及[术语表](../reference/glossary.md)定义的词。
6. 标题从单个 `#` 开始逐级递进；表格只用于结构化比较，步骤使用有序列表。
7. 路径统一使用仓库相对路径和 `/`；PowerShell 命令使用 `powershell` 代码块。
8. 状态不要写“基本完成”“已收口”等不可验证词，改为具体的实现、验证或待办条件。

## 文件与链接

- 目录名和普通 Markdown 文件名使用小写 kebab-case，目录索引固定为 `README.md`。
- 所有内部链接使用相对路径；改名或移动时同步调用方、代码注释、Issue 模板和生成源说明。
- 标题锚点不作为唯一长期标识；能链接文件就不依赖易变的深层锚点。
- 图片放 `docs/images/`，使用描述性文件名和 alt 文本；没有被文档引用的图片不提交。
- 文本使用 UTF-8、LF 和末尾换行。

## API 与生成内容

HTTP API 由 OpenAPI 维护，Go package API 由源码注释和 `doc.go` 维护。普通 Markdown 只解释架构和使用边界，不复制完整路由、DTO 或 package 成员清单。

## 审查清单

- 文档职责是否可以由标题和首段判断；
- 是否把历史结果写成当前事实；
- 是否复制了另一个权威文档的大段内容；
- 命令、路径、版本与当前配置是否一致；
- 相对链接、标题层级、代码围栏、图片与 LF 是否有效；
- 是否泄露 secret、私人路径或真实媒体信息。
