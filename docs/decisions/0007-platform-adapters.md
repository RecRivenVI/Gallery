# ADR-0007：平台适配层

- 状态：Accepted
- 日期：2026-07-16

## 上下文

路径比较、文件身份、锁、AppDirs、磁盘与进程控制在各操作系统不同。如果平台 API 进入领域或应用层，核心语义和测试会被条件分支污染。

## 决策

- 平台中立接口放在 `internal/ports` 或对应能力的最小接口中。
- OS 实现放在 `internal/platform/<capability>`，使用文件后缀与 build constraint。
- 通用业务文件不通过 `runtime.GOOS` 选择行为。
- 平台无法保证声明的安全边界时 fail-closed，而不是静默降级。
- 支持声明必须来自目标系统真实运行证据，交叉编译不算支持。

## 理由

显式适配器让领域语义可复核，避免 Win32 细节泄漏；fail-closed 保护文件身份、锁和进程树等安全边界；真实运行要求防止把“能编译”包装成“受支持”。

## 影响

- 新 OS 能力需要端口、具体实现和该平台门禁。
- 后缀与 build constraint 必须一致。
- Windows x64 RC 前仅推进 Windows 实现；现有非 Windows 文件保持未验证状态。

## 重新审议

若某能力可以完全由标准库跨平台实现，可删除多余适配器，但必须保留相同失败语义和测试边界。
