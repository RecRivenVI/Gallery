# Web 共享设计系统

本文件描述 `web/src/design/` 中当前使用的共享设计语言。代码中的 token 和组件实现是最终执行来源。

## 设计目标

Gallery 使用克制、内容优先的工具型界面。用户端强调媒体浏览和连续查看，管理端强调状态密度和可核对的操作；两者保持一致的字体、表面、状态色、焦点和交互反馈。

## Token

`tokens.css` 定义语义 token，业务组件不得直接建立第二套颜色或时序体系。

- 主题：`system`、`light`、`dark`、`high-contrast`。
- 密度：`comfortable` 与 `compact`。
- 表面：页面、内容、浮层和沉浸遮罩按语义分层。
- 文字：主要内容、辅助信息和弱提示保持稳定层级。
- 状态：成功、警告、危险和信息使用独立语义色；颜色不能成为唯一状态提示。
- 焦点：可见焦点环与选中、悬停、警告分离。
- 形状：主要控件和容器接近方正；微型状态点与沉浸式媒体控制可按语义例外处理。

## 基础组件

`primitives.tsx` 基于 React Aria 提供按钮、图标按钮、文本字段、选择、复选框、开关、徽标、加载指示、空状态、错误状态、对话框、菜单、标签页、工具提示和通知等基础组件。

使用原则：

- 交互控件必须有可访问名称，纯图标按钮必须提供文本标签。
- `EmptyState` 只表示请求成功但没有结果；加载、无权限和失败使用各自状态。
- 阻塞失败和需要用户决策的冲突保留在页面或对话框中，不只依赖会消失的通知。
- 危险通知默认不自动消失；一次性密文等敏感结果不得进入普通通知、日志或截图。
- 字段错误与对应输入建立程序化关联，服务端稳定错误码和关联 ID 可作为诊断信息显示。

## 响应式布局

- 布局轨道必须允许内容收缩，协议字段、标识和路径可换行，不能依赖固定最小宽度撑开页面。
- 桌面使用常驻侧栏；窄屏使用模态导航，并确保焦点陷阱、Escape 关闭和焦点返还。
- 管理端表格在窄屏转换为仍保留列标签的堆叠结构，而不是丢失表头语义。
- 用户端媒体网格通过固定分块和视口附近挂载控制 DOM 规模；占位高度只服务布局，不代表客户端数据上限。

## 可访问性

- 所有功能必须可用键盘完成，焦点顺序与视觉顺序一致。
- 状态、错误、进行中和完成信息同时提供文字或可访问名称。
- `prefers-reduced-motion` 既在 CSS token 层归零，也在逻辑动效层停止创建动画。
- 高对比主题使用系统色语义；不得用自定义背景覆盖 forced-colors 下的按钮、链接和焦点语义。
- 自动化 axe 检查是回归手段，不等同于真实设备、物理高对比或人工屏幕阅读器验收。

## 文案

界面文案直接说明对象、动作和结果。危险操作必须说明影响范围；错误信息先给出用户可执行的下一步，再附稳定错误码或关联 ID。不得把内部阶段编号、开发日志或未经核实的能力写入产品界面。
