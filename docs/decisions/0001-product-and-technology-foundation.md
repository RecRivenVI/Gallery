# ADR-0001：产品与技术基础

- 状态：Accepted
- 日期：2026-07-16

## 上下文

Gallery 需要在个人设备上处理大型只读媒体目录，保存不可重建用户事实，并向多种客户端提供一致能力。核心不能依赖某个 Web 框架、桌面壳或外部数据库服务。

## 决策

- 产品采用独立净室设计，不兼容其它产品的数据、配置或 API。
- 后端使用 Go 模块化单体，服务命令为 `galleryd`，CLI 为 `galleryctl`。
- 持久化使用进程内 SQLite，并把不可重建 control 事实与可重建 Catalog 投影分库。
- 公开能力 API-first，通过 OpenAPI 和版本化 WebSocket 暴露。
- Web、PWA、桌面壳和其它客户端都是可替换消费者，不拥有核心业务语义。

## 理由

Go 适合构建单二进制、并发有界的本地服务；SQLite 降低个人部署运维成本；模块化单体避免在边界尚未冻结时引入分布式事务；API-first 让浏览器和未来客户端共享同一授权与查询语义。

## 影响

- 业务实现进入 `internal/`，公开 package 只承担明确兼容责任。
- 跨库一致性必须用 publication、Job 和恢复协议表达，不能依赖跨库事务假象。
- Node.js 只参与可选 Web 构建，不是 `galleryd` 运行依赖。
- 如果未来拆分服务，必须先保留现有 API、数据所有权和失败语义。

## 重新审议

只有单进程/SQLite 在已记录的 Windows x64 目标规模上无法满足正确性或运维要求，且有可复现证据时，才重新评估存储或部署形态。
