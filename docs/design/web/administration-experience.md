# 管理端体验

管理端位于 `/manage/`，面向需要明确权限的配置、扫描、规则、安全、维护和治理任务。它是 `galleryd` 的 Web 管理界面，不是桌面进程控制器。

## 信息架构

| 路由 | 主要内容 |
| --- | --- |
| `/manage/` | 当前实例、资源和任务概览 |
| `/manage/scans` | Library、Source、Binding、扫描启动和任务列表 |
| `/manage/scans/:jobId` | Job、Attempt、取消与重试 |
| `/manage/diagnostics` | 维护、备份、恢复校验和诊断能力 |
| `/manage/security` | Session、Token、Share、账户、Grant 和审计记录 |
| `/manage/rules` | 规则包、版本、草稿和 Binding |
| `/manage/rules/:packageId` | Schema 表单、无损文本、调试、发布和生命周期操作 |
| `/manage/governance` | Binding issue、结构决策、孤儿候选和人工解绑 |

桌面使用紧凑侧栏和上下文工具区；窄屏使用可关闭的模态导航。页面名称按长期资源和用户任务组织，不使用阶段编号或证据编号。

## 操作模式

- 列表以服务端 keyset 页为边界，只渲染当前页或有界窗口；已访问页可缓存，但不得表现为完整服务端数据集。
- 后台刷新原位更新状态，不让轮询结果反复触发大幅入场动画。
- 表单在提交前显示本地校验；服务端 Schema、权限、CAS 和状态机仍是最终权威。
- 规则草稿同时支持结构化表单和无损文本。无法安全结构化表达的内容保持原始文本，不静默丢弃未知字段或精确数字。
- Dry Run、Explain 和 Trace 使用明确的合成输入；当前管理端不借此读取真实 Source 或绕过扫描边界。
- 维护、恢复、密文创建和其他高影响操作使用明确确认，说明对象、范围和不可逆部分。
- 取消和重试必须展示目标 Job 与当前状态；界面不把已受理请求提前显示为完成。

## 治理

治理页把冲突和身份修正作为有生命周期的资源处理。Binding issue、结构决定、孤儿决定和人工解绑分别保留服务端状态、版本与冲突结果。撤销不是客户端删除历史，而是调用明确的后端操作并处理可能的 `409 CONFLICT`。

## 安全与敏感信息

- capability 决定控件是否可用；服务端再次授权每个请求。
- Token 等一次性密文只在创建结果对话框显示，不写入通知、日志、测试截图或持久客户端状态。
- 管理端不显示 secret、Cookie、真实私密 metadata 或不必要的完整媒体路径。
- 管理端不提供启动、停止或重启 `galleryd` 的桌面 bridge，也不直接编辑进程外配置文件。

## 失败与恢复

续页失败保留当前页并提供原位重试；筛选变化回到第一页。结构化错误显示稳定 code 和 correlation ID。实时连接恢复后重新获取当前页面依赖的 HTTP 快照，不能只依赖漏失事件推导最终状态。
